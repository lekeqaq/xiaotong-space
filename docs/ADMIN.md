# 内容管理后台

后台与网站运行在同一个 Nuxt Node 服务内，不需要独立后端。入口为 `/admin`，界面基于 Vuetify 4，使用独立的工作台布局和深浅主题。当前支持文章、首页照片与便签、图片管理、发布历史和备份；项目内容仍通过 `content/projects/*.md` 与 Nuxt Content 管理。

## 界面结构

后台统一使用 Vuetify 的导航抽屉、卡片、按钮、表单、标签页和弹窗。桌面显示固定侧栏，手机使用抽屉。导航、顶栏和主题容器由持久化 `admin` 布局承载，菜单切换只更新内容区，保留浏览器前进／后退；编辑页的「全部文章」返回键固定在顶栏，滚动正文后仍可使用。登录使用独立标签与密码显示切换，后台文本框、分类与标签使用 Vuetify 表单组件，日期使用中文 `VDateInput` 日历，统一使用圆角边框与聚焦颜色；移入回收站使用红色按钮。编辑页统一设置保存状态与页面操作区。弹窗使用 `VDialog`，打开时锁定页面背景滚动，关闭后恢复原位置；标题与关闭按钮固定，内容区独立滚动，支持 Escape、焦点约束和关闭后焦点恢复。回收站、图片删除和版本恢复使用同一套确认弹窗。

`modules/admin-vuetify.ts` 按需注册组件，`app/plugins/vuetify.ts` 统一配置主题、Lucide 图标和组件默认值；`AdminProvider.vue` 与后台样式仅供后台页面使用。没有导入 Vuetify 的全局重置或通用 html/body 样式，以免影响公开网站。仅后台根节点设置可识别的滚动容器，让 Vuetify 的 `block` 策略锁住页面。主题切换使用 320 ms 渐变，并支持减少动态效果的系统偏好；工作台内容区随窗口宽度扩展。

完整预览使用同源 `/admin/preview` 页面，与后台样式隔离，在 iframe 内触发真实的响应式布局。该页面要求登录，通过校验来源和发送窗口的 `postMessage` 接收当前草稿；草稿不进入预览 URL。预览中的站点链接保持在当前草稿，照片与便签按钮仍可交互。

## 首次启动

```sh
pnpm install --frozen-lockfile
cp .env.example .env # 已有 .env 时不要覆盖
# 本地将 .env 中 NUXT_PUBLIC_SITE_URL 改为 http://localhost:3000
pnpm admin:password
pnpm dev
```

`admin:password` 在终端中提示输入两次密码，不回显。当前密码工具要求 8–12 个字符，通过 scrypt 哈希后写入 `.env`，不保存明文。默认账号为 `admin`，可修改 `NUXT_ADMIN_USERNAME`。没有配置密码时后台无法登录，没有默认密码。

如由部署平台管理环境变量，在安全终端运行 `pnpm admin:password --print-hash`，将结果设置为 `NUXT_ADMIN_PASSWORD_HASH`。任何后台凭证都不要放入 `NUXT_PUBLIC_*`。环境变量变更后重启服务；修改账号或密码会使之前的登录会话失效。

## 写文章

1. 登录后在文章列表中点击「新建文章」。
2. 编辑标题、摘要和正文，选择分类、标签和封面。正文使用 [Vditor](https://github.com/Vanessa219/vditor) 开源富文本编辑器，支持标题、加粗、链接、列表、引用、代码块、表格和图片；可直接粘贴 Markdown 源文并显示格式。底层仍保存 Markdown，现有 MDC 提示块以可编辑源码块保留。
3. 设置文章地址和发布日期。地址只接受小写英文、数字和连字符；首次发布后地址固定，撤回发布也不会解锁。
4. 修改后点击「保存草稿」或按 Cmd/Ctrl + S 手动保存，发布前先保存草稿。请检查保存状态，保存失败时内容仍留在当前编辑页。
5. 点击顶部「预览」检查完整文章布局，预览与正式文章共用 Markdown/MDC 渲染、代码高亮和提示块。正文区不展示实时预览，也不在输入时发送预览请求。完整预览支持桌面（1280 px）和手机（390 px）视口，并独立滚动。编辑器不自动保存，也不启用本地草稿缓存。
6. 点击「发布文章」后页面、文章列表、首页最新笔记、RSS、sitemap 立即读取新发布版本，无需重新构建。

草稿、草稿修改和发布历史只通过登录后的管理接口读取。修改已发布文章时，线上继续展示上一发布版本，直到再次发布。发布要求标题、摘要、正文、分类和封面完整；不支持未来日期的定时发布。阅读时间按正文自动估算。

文章列表支持搜索、草稿／已发布筛选和回收站。撤回发布会从公开页面、RSS、sitemap 隐藏文章，保留草稿和历史。移入回收站也会隐藏文章；从回收站恢复后，如原本存在发布版本，该版本会重新展示。回收站中的「永久删除」会在确认后删除文章草稿、发布内容和全部历史版本，无法通过后台恢复；只能删除回收站中的文章，且会校验版本以避免误删其他窗口刚恢复或更新的文章。图片文件保留在图片库，删除文章后不再被该文章及其历史引用，没有其他引用的上传图片可以单独删除。之前下载的备份不受影响。

每次发布保存一个历史版本。恢复历史只替换草稿，不会直接替换线上版本。历史版本中的图片也算被引用，避免恢复后图片丢失。两个窗口同时编辑时，旧版本保存会被拒绝；重新加载前可先复制当前正文，避免丢失未保存的修改。

## 维护首页

首页编辑初始包含 5 张照片和 6 句便签话术。支持新增、删除、更换照片、编辑配文和图片描述、修改话术并保留换行。

生活照片以响应式卡片网格展示，每张卡片包含图片、配文、图片描述和排序工具，手机上改为单列。拖动把手或使用上下按钮排序，每个模块保留 1–30 条。照片配文不超过 80 字符、图片描述不超过 160 字符、话术不超过 100 字符。修改后点击「保存草稿」；「预览首页」在独立页面中用真实网站组件展示当前草稿，可以切换桌面／手机视口，点击检查照片与话术轮播。「发布首页」一次性更新线上两组内容。

首页也保留发布历史，可以恢复到草稿后再发布。

## 图片

支持 JPG、PNG、WebP、AVIF，单文件最大 10 MB、最多 4000 万像素。服务器解码文件，修正旋转、移除元数据，将尺寸限制在 2560 × 2560 内并压缩为 WebP。上传文件以随机名称存储，通过 `/media/<uuid>.webp` 提供访问；不会覆盖同名文件。

图片库可以搜索、按来源筛选、查看原图和引用位置、复制地址，或直接为正文、封面和首页选择图片。网站内置素材只供选择，不能从后台删除；上传图片被草稿、已发布内容、回收站或发布历史引用时也禁止删除。图片地址本身可以公开访问，请不要上传保密文件。

## 内容存储与迁移

运行目录由服务端环境变量 `NUXT_ADMIN_DATA_DIR` 决定，默认 `.data/admin`：

```text
.data/admin/
├── content.sqlite      # 草稿、发布版本、历史、媒体元数据及会话
├── content.sqlite-wal  # SQLite 运行文件（可能存在）
├── content.sqlite-shm
└── uploads/            # 经过处理的上传图片
```

首次访问内容时创建数据库并导入 `server/assets/admin-seed.json` 中的现有文章以及 `shared/admin.ts` 中的首页初始配置，保留文章地址、日期与正文。导入在事务中完成，成功后只执行一次，不会在重启或重新部署时覆盖后台修改。

`content/writing/*.md` 保留为迁移来源，运行中的文章以后台数据库为准。`pnpm admin:seed` 可在开发阶段重新生成首次导入种子，但不会覆盖已初始化的数据库。不要通过删数据库更新线上内容。

首页、文章及 RSS、sitemap 使用运行时数据，不再构建时预渲染；项目与关于页面仍可预渲染。文章已退出 Nuxt Content 公开集合，避免旧的构建索引继续提供撤回后的文章。公开接口只返回发布版本，管理接口要求登录。后台设置 `noindex`，robots 禁止抓取后台路径。

## 生产部署

使用腾讯云和 1Panel 部署的完整步骤、域名配置和 Docker 编排文件，见 [1Panel 部署指南](DEPLOY-1PANEL.md)。

需要 Node.js 22+、单实例 Nuxt 服务和持久化磁盘。部署前在服务器设置：

```text
NUXT_PUBLIC_SITE_URL=https://你的实际域名
NUXT_ADMIN_USERNAME=admin
NUXT_ADMIN_PASSWORD_HASH=scrypt:...（通过密码工具生成）
NUXT_ADMIN_DATA_DIR=/srv/xiaotong-data/admin
```

```sh
pnpm install --frozen-lockfile
pnpm build
HOST=127.0.0.1 PORT=3000 node --env-file-if-exists=.env .output/server/index.mjs
```

正式站点使用 HTTPS，并通过反向代理转发到 Nuxt。`NUXT_PUBLIC_SITE_URL` 必须与浏览器访问后台的域名一致，它也是管理写入接口检查 Origin 的依据。登录 Cookie 为 HttpOnly、SameSite=Strict，HTTPS 下启用 Secure，12 小时后过期；所有管理写入接口检查来源和专用请求头。登录连续失败 5 次后，同一连接来源限流 15 分钟。未经明确配置，不信任客户端发送的转发 IP。

应用用户必须能够读写持久化目录。代码部署目录可以替换，内容目录不能清空，也不能放入临时容器文件系统。不要将 macOS 构建直接复制到 Linux：SQLite、Sharp 依赖原生模块，应在目标操作系统和架构构建。

纯静态生成不支持内容后台，因此不再作为完整站点的部署方式。当前方案针对单实例；多个服务器实例或没有持久化磁盘的平台需要调整为共享数据库和对象存储。

## 备份与恢复

后台桌面侧栏的「下载完整备份」导出 `.tar.gz`，包含 SQLite 一致性快照、上传图片和格式清单。备份期间暂时拒绝内容修改，请稍后重试。备份不会包含 `.env` 或有效登录会话；内置图片和项目 Markdown 仍随代码仓库保存。

手机端通过左上角打开导航抽屉；也可使用页头下载按钮导出完整备份。建议定期将备份保存在服务器之外。备份包含未发布内容，应妥善保管。

恢复前先停止所有 Nuxt 实例，再执行：

```sh
pnpm admin:restore /path/xiaotong-backup.tar.gz --server-stopped --data-dir /srv/xiaotong-data/admin
```

恢复工具检查归档路径、文件类型、数据库完整性和媒体文件。原数据目录会保留为 `admin.before-restore-<时间戳>`；恢复后的会话全部失效，需要重新登录。确认新数据可用后再自行清理旧目录。`--server-stopped` 表示操作者已停止服务，工具不会自动停止服务器。

## 验证

```sh
pnpm lint
pnpm typecheck
pnpm build
pnpm test
pnpm test:admin
PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e
```

管理接口测试使用临时内容目录，覆盖登录保护、来源校验、草稿隔离、发布／撤回／回收站、版本冲突、历史恢复、首页排序、图片上传与引用保护、备份恢复和进程重启后的持久化。

浏览器测试使用临时测试账号与临时数据库，不会修改真实后台内容；覆盖桌面与手机上的登录、文章编辑、手动保存、预览、发布、首页轮播预览、图片库、深色主题、输入框聚焦、菜单无刷新切换、滚动后返回和退出登录。测试账号只存在于测试启动参数中，不是网站默认凭证。
